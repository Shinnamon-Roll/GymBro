\chapter{คู่มือการติดตั้งและการใช้งานระบบอย่างละเอียด (Comprehensive System Installation and Deployment Guide)}

ภาคผนวกนี้จัดทำขึ้นเพื่อเป็นคู่มือการปฏิบัติงานแบบทีละขั้นตอน (Step-by-step Manual) ที่มีความละเอียดและครอบคลุมทุกกระบวนการ สำหรับนักพัฒนาซอฟต์แวร์และผู้ดูแลระบบ (System Administrators) ในการติดตั้งระบบบริหารจัดการยิม (GymBro Management System) ตั้งแต่เริ่มต้น (From Scratch) เนื้อหาครอบคลุมตั้งแต่การตรวจสอบความพร้อมของซอฟต์แวร์พื้นฐาน การตั้งค่าสภาพแวดล้อม การติดตั้งไลบรารี ไปจนถึงการนำระบบขึ้นใช้งานจริง (Production Deployment) เพื่อให้มั่นใจว่าการติดตั้งจะเป็นไปอย่างราบรื่นและปราศจากข้อผิดพลาด

\section{ความต้องการเบื้องต้นของระบบ (Prerequisites)}
ก่อนเริ่มดำเนินการติดตั้ง ผู้ปฏิบัติงานต้องตรวจสอบให้แน่ใจว่าเครื่องคอมพิวเตอร์หรือเซิร์ฟเวอร์ที่ใช้ในการพัฒนาและการใช้งานจริง ได้รับการติดตั้งและตั้งค่าซอฟต์แวร์พื้นฐานดังต่อไปนี้อย่างถูกต้องและครบถ้วน ซึ่งถือเป็นปัจจัยวิกฤต (Critical Factors) ต่อการทำงานของระบบ

\subsection{ซอฟต์แวร์ที่จำเป็น (Required Software)}
\begin{itemize}
    \item \textbf{Node.js (เวอร์ชัน 18.x หรือสูงกว่า)}: 
    \begin{itemize}
        \item \textbf{บทบาท}: เป็นสภาพแวดล้อมรันไทม์หลัก (Core Runtime Environment) สำหรับการประมวลผลโค้ด JavaScript ฝั่ง Backend ของระบบ
        \item \textbf{ข้อแนะนำ}: ควรเลือกใช้เวอร์ชัน Long-Term Support (LTS) เช่น v18.16.0 เพื่อความเสถียรสูงสุดและการรองรับไลบรารีรุ่นใหม่
        \item \textbf{การตรวจสอบ}: พิมพ์คำสั่ง \texttt{node -v} ในเทอร์มินัล ผลลัพธ์ควรแสดงเวอร์ชัน เช่น \texttt{v18.16.0}
    \end{itemize}
    
    \item \textbf{PostgreSQL (เวอร์ชัน 14.x หรือสูงกว่า)}:
    \begin{itemize}
        \item \textbf{บทบาท}: ระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (RDBMS) หลักที่ใช้สำหรับจัดเก็บข้อมูลถาวร (Persistent Data Storage) ของระบบ
        \item \textbf{เหตุผลที่เลือกใช้}: เนื่องจากมีความทนทาน (Robustness), รองรับคุณสมบัติ ACID อย่างสมบูรณ์, และมีความสามารถในการทำ Indexing ขั้นสูง ซึ่งจำเป็นต่อการจัดการธุรกรรมการจองที่มีความซับซ้อน
        \item \textbf{การตรวจสอบ}: พิมพ์คำสั่ง \texttt{psql --version} และตรวจสอบสถานะบริการผ่านคำสั่ง \texttt{sudo service postgresql status} (Linux) หรือตรวจสอบใน Services panel (Windows)
    \end{itemize}
    
    \item \textbf{Git (เวอร์ชัน 2.x)}:
    \begin{itemize}
        \item \textbf{บทบาท}: ระบบควบคุมเวอร์ชัน (Version Control System) สำหรับการดึงซอร์สโค้ดจาก Repository
        \item \textbf{การตรวจสอบ}: พิมพ์คำสั่ง \texttt{git --version}
    \end{itemize}
    
    \item \textbf{Code Editor / IDE}:
    \begin{itemize}
        \item \textbf{ข้อแนะนำ}: แนะนำให้ใช้ Visual Studio Code (VS Code) เนื่องจากมีการรองรับภาษา JavaScript ที่ยอดเยี่ยม มีเครื่องมือ Debugging ในตัว และมี Terminal ภายใน
        \item \textbf{ส่วนขยาย (Extensions)}: ควรติดตั้ง "ESLint", "Prettier", และ "DotENV" เพื่อเพิ่มประสิทธิภาพในการพัฒนาและตรวจสอบคุณภาพโค้ด
    \end{itemize}
\end{itemize}

\section{การกำหนดค่าสภาพแวดล้อม (Environment Configuration)}
การกำหนดค่าตัวแปรสภาพแวดล้อม (Environment Variables) อย่างถูกต้องมีความสำคัญสูงสุดต่อความปลอดภัยและการทำงานของแอปพลิเคชัน ระบบอาศัยไฟล์ \texttt{.env} ในการจัดการข้อมูลลับ (Sensitive Credentials) และค่าการตั้งค่าต่างๆ

\subsection{การตั้งค่าฐานข้อมูล (Database Setup)}
1. เปิดเทอร์มินัลหรือเครื่องมือจัดการฐานข้อมูล เช่น pgAdmin หรือ DBeaver
2. เชื่อมต่อเข้าสู่ PostgreSQL server:
\begin{lstlisting}[language=bash, frame=single]
psql -U postgres
\end{lstlisting}
3. สร้างฐานข้อมูลใหม่สำหรับโปรเจกต์:
\begin{lstlisting}[language=sql, frame=single]
CREATE DATABASE gymbro_db;
\end{lstlisting}
4. (ทางเลือก) สร้างผู้ใช้งานเฉพาะสำหรับแอปพลิเคชัน:
\begin{lstlisting}[language=sql, frame=single]
CREATE USER gym_admin WITH ENCRYPTED PASSWORD 'secure_password_123';
GRANT ALL PRIVILEGES ON DATABASE gymbro_db TO gym_admin;
\end{lstlisting}

\subsection{การสร้างไฟล์ .env (Setting up the .env File)}
1. ไปที่ไดเรกทอรีราก (Root Directory) ของโปรเจกต์
2. สร้างไฟล์ใหม่ชื่อ \texttt{.env}
3. คัดลอกแม่แบบการตั้งค่าต่อไปนี้และกรอกข้อมูลให้ตรงกับสภาพแวดล้อมของท่าน:

\begin{lstlisting}[frame=single]
# การตั้งค่าเซิร์ฟเวอร์
PORT=3000
NODE_ENV=development

# การเชื่อมต่อฐานข้อมูล (สำหรับเครื่อง Local)
DB_HOST=localhost
DB_PORT=5432
DB_NAME=gymbro_db
DB_USER=gym_admin
DB_PASS=secure_password_123
DB_DIALECT=postgres

# Connection String (ทางเลือกสำหรับ Cloud Deployment)
# DATABASE_URL=postgres://user:pass@host:port/dbname

# กุญแจความปลอดภัย (Security Keys)
JWT_SECRET=your_super_secret_jwt_key_32_chars_long
SESSION_SECRET=another_long_random_string_for_sessions

# บริการภายนอก (ถ้ามี)
# SMTP_HOST=smtp.gmail.com
# SMTP_USER=your_email@gmail.com
# SMTP_PASS=your_app_password
\end{lstlisting}

\textbf{คำอธิบายตัวแปรที่สำคัญ:}
\begin{itemize}
    \item \texttt{PORT}: หมายเลขพอร์ตที่ Express server จะเปิดรอรับการเชื่อมต่อ (ค่าเริ่มต้นคือ 3000)
    \item \texttt{DB\_*}: รายละเอียดการเชื่อมต่อฐานข้อมูล PostgreSQL ต้องตรงกับฐานข้อมูลที่สร้างไว้ในขั้นตอนก่อนหน้า
    \item \texttt{JWT\_SECRET}: กุญแจส่วนตัว (Private Key) สำหรับใช้ในการลงลายมือชื่อและตรวจสอบ JSON Web Tokens เพื่อการยืนยันตัวตน ห้ามเปิดเผยข้อมูลนี้
\end{itemize}

\section{ขั้นตอนการติดตั้ง (Installation Process)}
ปฏิบัติตามขั้นตอนอย่างเคร่งครัดเพื่อติดตั้งซอร์สโค้ดและไลบรารีที่จำเป็นลงในเครื่องคอมพิวเตอร์

\subsection{การโคลน Repository (Cloning the Repository)}
เปิดเทอร์มินัลและไปยังไดเรกทอรีที่ต้องการทำงาน จากนั้นพิมพ์คำสั่ง:
\begin{lstlisting}[language=bash, frame=single]
git clone https://github.com/username/gymbro-management-system.git
cd gymbro-management-system
\end{lstlisting}

\subsection{การติดตั้ง Dependencies (Installing Dependencies)}
โปรเจกต์นี้ใช้งานแพ็กเกจ Node.js จำนวนมากซึ่งระบุไว้ในไฟล์ \texttt{package.json} ให้ทำการติดตั้งโดยใช้ npm (Node Package Manager):
\begin{lstlisting}[language=bash, frame=single]
npm install
\end{lstlisting}

\textbf{คำอธิบาย Dependencies หลัก:}
\begin{itemize}
    \item \texttt{express}: เว็บเฟรมเวิร์กสำหรับจัดการ HTTP requests
    \item \texttt{sequelize}: Object-Relational Mapper (ORM) สำหรับติดต่อกับฐานข้อมูล
    \item \texttt{pg} \& \texttt{pg-hstore}: ไดรเวอร์ PostgreSQL สำหรับ Sequelize
    \item \texttt{ejs}: Templating engine สำหรับการแสดงผลฝั่งเซิร์ฟเวอร์ (Server-side rendering)
    \item \texttt{bcryptjs}: สำหรับการเข้ารหัสรหัสผ่าน (Hashing) อย่างปลอดภัย
    \item \texttt{jsonwebtoken}: สำหรับสร้าง Access Tokens
    \item \texttt{dotenv}: สำหรับโหลดตัวแปรสภาพแวดล้อม
\end{itemize}

\section{การเริ่มต้นฐานข้อมูล (Database Initialization)}
ก่อนที่จะรันแอปพลิเคชัน จำเป็นต้องทำการปรับปรุงโครงสร้างฐานข้อมูล (Schema Synchronization) และนำเข้าข้อมูลตั้งต้น (Seed Data)

\subsection{การรัน Migrations (Running Migrations)}
Sequelize migrations ช่วยให้โครงสร้างฐานข้อมูลตรงกับ Models ในโค้ด ให้รันคำสั่งต่อไปนี้เพื่อสร้างตารางที่จำเป็น (\texttt{Users}, \texttt{Trainers}, \texttt{Bookings} ฯลฯ):
\begin{lstlisting}[language=bash, frame=single]
npx sequelize-cli db:migrate
\end{lstlisting}
\textit{ผลลัพธ์ควรแสดงว่าไฟล์ migration ต่างๆ ถูกประมวลผลสำเร็จ}

\subsection{การนำเข้าข้อมูลตัวอย่าง (Seeding Data)}
เพื่อความสะดวกในการทดสอบระบบ ควรนำเข้าข้อมูลตัวอย่าง (เช่น บัญชีแอดมิน, รายชื่อเทรนเนอร์, รายการอุปกรณ์) โดยใช้คำสั่ง:
\begin{lstlisting}[language=bash, frame=single]
npx sequelize-cli db:seed:all
\end{lstlisting}
\textit{คำสั่งนี้จะเพิ่มข้อมูลลงในตารางตามที่กำหนดไว้ในโฟลเดอร์ \texttt{seeders}}

\section{การรันและใช้งานระบบ (Execution and Deployment)}

\subsection{สำหรับการพัฒนา (Local Development)}
ในขั้นตอนการพัฒนา แนะนำให้ใช้ \texttt{nodemon} เพื่อให้เซิร์ฟเวอร์รีสตาร์ทอัตโนมัติเมื่อมีการแก้ไขโค้ด
\begin{lstlisting}[language=bash, frame=single]
npm run dev
\end{lstlisting}
เข้าใช้งานระบบได้ที่ \texttt{http://localhost:3000}

\subsection{สำหรับการใช้งานจริง (Production Deployment)}
ในสภาพแวดล้อม Production ควรใช้ Process Manager เช่น PM2 เพื่อให้มั่นใจว่าแอปพลิเคชันจะทำงานตลอดเวลาและรีสตาร์ทเองได้หากเกิดข้อผิดพลาด
1. ติดตั้ง PM2 แบบ Global:
\begin{lstlisting}[language=bash, frame=single]
npm install pm2 -g
\end{lstlisting}
2. สตาร์ทแอปพลิเคชัน:
\begin{lstlisting}[language=bash, frame=single]
pm2 start server.js --name "gymbro-api"
\end{lstlisting}
3. ตรวจสอบสถานะ:
\begin{lstlisting}[language=bash, frame=single]
pm2 status
pm2 logs gymbro-api
\end{lstlisting}

\chapter{อ้างอิงรหัสต้นฉบับหลักของระบบ (Core System Source Code Reference)}

ภาคผนวกส่วนนี้ทำหน้าที่เป็นเอกสารอ้างอิงทางเทคนิคสำหรับตรรกะหลัก (Core Logic) และสถาปัตยกรรมของระบบ GymBro Management System โดยนำเสนอส่วนสำคัญของรหัสต้นฉบับ (Source Code) พร้อมคำอธิบายแทรกในบรรทัด (Inline Comments) อย่างละเอียด เพื่ออธิบายการทำงาน การไหลของข้อมูล (Control Flow) และรูปแบบการออกแบบ (Design Patterns) ที่ใช้ ตัวอย่างโค้ดเหล่านี้แสดงให้เห็นถึงการนำไปใช้จริงของฟีเจอร์หลัก เช่น การตั้งค่าเซิร์ฟเวอร์, การสร้างแบบจำลองข้อมูล, ตรรกะทางธุรกิจ, และการแสดงผล Frontend แบบไดนามิก

\section{จุดเข้าทำงานหลักของแอปพลิเคชัน (Main Application Entry Point - server.js)}
ไฟล์ \texttt{server.js} เปรียบเสมือนหัวใจของระบบ Backend ทำหน้าที่เริ่มต้น Express app, กำหนดค่า Middleware (CORS, JSON parsing), เชื่อมต่อฐานข้อมูล, และกำหนดเส้นทาง API (Routes)

\begin{lstlisting}[language=JavaScript, caption={การตั้งค่าเซิร์ฟเวอร์และการเริ่มต้นระบบ}, label={lst:server_js}]
// นำเข้าโมดูลที่จำเป็น
require("dotenv").config(); // โหลดตัวแปรสภาพแวดล้อมจากไฟล์ .env
const express = require("express"); // Web framework หลัก
const cors = require("cors"); // Middleware สำหรับจัดการ Cross-Origin Resource Sharing
const sequelize = require("./db"); // Instance การเชื่อมต่อฐานข้อมูล

// นำเข้า Models เพื่อให้มั่นใจว่าถูกลงทะเบียนกับ Sequelize แล้ว
const { Customers, Trainers, GymEquipments, TrainingSessions } = sequelize;

// สร้าง Instance ของ Express application
const app = express();

// --- การกำหนดค่า Middleware ---

// 1. CORS Setup: อนุญาตให้ Frontend ส่งคำขอเข้ามาได้
app.use(
  cors({
    origin: "http://localhost:5500", // อนุญาตเฉพาะ Origin นี้
    methods: ["GET", "POST", "PUT", "DELETE", "OPTIONS"], // HTTP methods ที่อนุญาต
    allowedHeaders: ["Content-Type", "Authorization"], // Headers ที่อนุญาต
  })
);

// 2. Body Parsing: แปลงข้อมูล JSON ที่ส่งเข้ามาใน Request Body
app.use(express.json());

// --- การเชื่อมต่อฐานข้อมูลและการซิงค์ (Database Connection & Synchronization) ---

/**
 * เชื่อมต่อกับฐานข้อมูล PostgreSQL และซิงค์ Models
 * การใช้ 'alter: true' ช่วยให้ Sequelize อัปเดตตารางให้ตรงกับ Models
 * โดยไม่ลบข้อมูลเดิม (มีประโยชน์มากในช่วงพัฒนา)
 */
sequelize.authenticate()
  .then(() => {
    console.log("Database connection established successfully.");
    return sequelize.sync({ alter: true }); 
  })
  .then(() => {
    console.log("Database models synchronized.");
  })
  .catch((err) => {
    console.error("Unable to connect to the database:", err);
  });

// --- การกำหนดเส้นทาง (Route Definitions) ---

// Login Endpoint
app.post("/api/login", async (req, res) => {
  const { email, phone } = req.body;
  
  try {
    // ตรวจสอบ Admin แบบ Hardcoded (เพื่อความง่ายในโปรเจกต์การศึกษานี้)
    if (email === "admin@gymbro.com" && phone === "123456") {
      return res.json({
        role: "admin",
        user: { id: 0, fullName: "Administrator", email: email },
        token: "mock-admin-token-123" // ในระบบจริงควรสร้าง JWT ที่ถูกต้อง
      });
    }

    // การยืนยันตัวตนสมาชิก (Member Authentication)
    const user = await Customers.findOne({ where: { email } });
    
    if (!user) {
      return res.status(404).json({ error: "User not found" });
    }

    // ตรวจสอบเบอร์โทรศัพท์ (ใช้แทนรหัสผ่านในระบบนี้)
    if (user.phone !== phone) {
      return res.status(401).json({ error: "Invalid credentials" });
    }

    // เข้าสู่ระบบสำเร็จ
    res.json({
      role: "user",
      user: user,
      token: `mock-user-token-${user.id}`
    });

  } catch (error) {
    console.error("Login error:", error);
    res.status(500).json({ error: "Internal server error" });
  }
});

// เริ่มต้นเซิร์ฟเวอร์
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Server is running on port ${PORT}`);
});
\end{lstlisting}

\section{การนิยามแบบจำลองข้อมูล Sequelize (models/TrainingSession.js)}
ส่วนนี้แสดงวิธีการนิยาม Data Models โดยใช้ Sequelize โมเดล \texttt{TrainingSession} เป็นตัวแทนของเหตุการณ์การจอง และมีความสัมพันธ์แบบ Foreign Key ไปยังลูกค้า, เทรนเนอร์, และอุปกรณ์

\begin{lstlisting}[language=JavaScript, caption={การนิยามโมเดล TrainingSession}, label={lst:model_session}]
const { DataTypes } = require("sequelize");

\section{ตรรกะหลักของ Controller (การตรวจสอบความขัดแย้งของการจอง)}
ตัวอย่างโค้ดจาก Booking Controller นี้แสดงอัลกอริทึมสำคัญที่ใช้ป้องกันการจองซ้อน (Double Bookings) โดยจะตรวจสอบช่วงเวลาที่ทับซ้อนกันของทั้งเทรนเนอร์และอุปกรณ์ก่อนที่จะยืนยันธุรกรรม

\begin{lstlisting}[language=JavaScript, caption={Booking Controller พร้อมการตรวจสอบความขัดแย้ง}, label={lst:controller_booking}]
const { Op } = require("sequelize");
const { TrainingSessions } = require("../models");

/**
 * createBooking
 * จัดการการสร้างเซสชันการฝึกซ้อมใหม่
 * ทำการตรวจสอบอย่างเข้มงวดเพื่อให้แน่ใจว่าทรัพยากรว่าง
 */
async function createBooking(req, res) {
  const { customerId, trainerId, equipmentId, sessionDate, duration } = req.body;
  
  // เริ่มต้น Database Transaction เพื่อความถูกต้องของข้อมูล (Atomicity)
  const t = await sequelize.transaction();

  try {
    // 1. คำนวณเวลาเริ่มต้นและเวลาสิ้นสุด
    const startTime = new Date(sessionDate);
    const endTime = new Date(startTime.getTime() + duration * 60000); // duration เป็นนาที

    // 2. ตรรกะการตรวจสอบความขัดแย้ง (Conflict Detection Logic)
    // เราต้องหาเซสชันที่มีอยู่แล้วซึ่งทับซ้อนกับเวลาที่ขอมา
    // เงื่อนไขการทับซ้อน: (StartA < EndB) AND (EndA > StartB)
    const conflictWhereClause = {
      [Op.or]: [
        // ตรวจสอบคิวเทรนเนอร์
        {
          trainerId: trainerId,
          sessionDate: { [Op.lt]: endTime },
          endDate: { [Op.gt]: startTime }
        },
        // ตรวจสอบคิวอุปกรณ์
        {
          equipmentId: equipmentId,
          sessionDate: { [Op.lt]: endTime },
          endDate: { [Op.gt]: startTime }
        }
      ]
    };

    // ค้นหาความขัดแย้งในฐานข้อมูล
    const existingConflict = await TrainingSessions.findOne({
      where: conflictWhereClause,
      transaction: t // รวมอยู่ใน transaction
    });

    // 3. จัดการกรณีเกิดความขัดแย้ง
    if (existingConflict) {
      await t.rollback(); // ยกเลิก transaction
      return res.status(409).json({ 
        error: "Conflict detected", 
        message: "เทรนเนอร์หรืออุปกรณ์ที่เลือกถูกจองแล้วในช่วงเวลานี้" 
      });
    }

    // 4. สร้างเซสชัน
    const newSession = await TrainingSessions.create({
      customerId,
      trainerId,
      equipmentId,
      sessionDate: startTime,
      endDate: endTime
    }, { transaction: t });

    // 5. ยืนยัน Transaction (Commit)
    await t.commit();
    
    // ส่งคืนผลลัพธ์สำเร็จ
    res.status(201).json({
      message: "การจองเสร็จสมบูรณ์",
      data: newSession
    });

  } catch (error) {
    // จัดการข้อผิดพลาดที่ไม่คาดคิด
    await t.rollback();
    console.error("Booking Error:", error);
    res.status(500).json({ error: "ไม่สามารถทำรายการจองได้" });
  }
}

        const isMySession = (s.customer && s.customer.id === myId);
        
        const tr = document.createElement('tr');
        // ไฮไลท์แถวที่เป็นรายการจองของเรา
        if (isMySession) {
            tr.className = "bg-accent/10 border-l-4 border-accent";
        }

        tr.innerHTML = `
            <td class="px-6 py-4">${timeStr}</td>
            <td class="px-6 py-4 font-bold">${s.customer.fullName}</td>
            <td class="px-6 py-4">${s.trainer ? s.trainer.trainerName : '-'}</td>
            <td class="px-6 py-4">${s.equipment.equipmentName}</td>
        `;
        tbody.appendChild(tr);
    });
}
